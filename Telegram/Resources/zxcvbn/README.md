# zxcvbn frequency lists

The two word lists in this directory are unmodified copies of third-party
frequency lists. They are read only at build time: the rules in
`Telegram/cmake/lib_zxcvbn.cmake` transliterate them and compile the result
into the `zxcvbn-c` password dictionary behind
`Telegram/SourceFiles/ui/passcode_strength.cpp`. No built artifact contains
these files: they are build-time inputs to a generated header. They are
tracked, so every source distribution of Telegram Desktop ships them
verbatim, and the attribution below covers those copies as well as the
dictionary compiled from them.

## Changes made

The lists are used as build-time input only: the word column is kept, each
word is transliterated to Latin letters by `zxcvbn_translit`, words that are
still non-ASCII or shorter than two letters are dropped, four OpenSubtitles
subtitle-markup strings (`chffffff`, `fntahoma`, `b1`, `i0`) are dropped,
and the result is compiled into the zxcvbn dictionary; the tracked files are
unmodified copies.
The count column only orders the words: the generated dictionary keeps a
word's rank, not its count.

## Reproducing the dictionary

The build performs these steps itself; run them by hand from the checkout
root after a Debug build to check that the generated header is reproducible.
`<dir>` is any scratch directory outside the checkout.

```
out/Telegram/Debug/zxcvbn_translit \
    Telegram/Resources/zxcvbn/ru_50k.txt <dir>/ru_50k-latin.txt
out/Telegram/Debug/zxcvbn_translit \
    Telegram/Resources/zxcvbn/uk_50k.txt <dir>/uk_50k-latin.txt
out/Telegram/Debug/zxcvbn_dictgen -o <dir>/dict-src.h \
    Telegram/ThirdParty/zxcvbn/words-eng_wiki.txt \
    Telegram/ThirdParty/zxcvbn/words-female.txt \
    Telegram/ThirdParty/zxcvbn/words-male.txt \
    Telegram/ThirdParty/zxcvbn/words-passwd.txt \
    Telegram/ThirdParty/zxcvbn/words-surname.txt \
    Telegram/ThirdParty/zxcvbn/words-tv_film.txt \
    <dir>/ru_50k-latin.txt \
    <dir>/uk_50k-latin.txt
cmp <dir>/dict-src.h out/Telegram/zxcvbn_gen/dict-src.h
```

The input order matters: the generator interleaves its inputs by rank, so
the six upstream lists come first, in the order `lib_zxcvbn.cmake` lists
them, followed by the Russian and then the Ukrainian intermediate. `cmp`
must report no difference.
