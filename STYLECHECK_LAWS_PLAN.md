# Единый свод правил стиля Telegram Desktop

В следующей сессии собери первый общий набор контрактов для Python и clang-tidy. Для каждого правила зафиксируй область действия, исключения и ожидаемые результаты на фрагментах C++. Tree-sitter подходит для синтаксиса и раскладки. Clang нужен для правил, зависящих от типов и семантики C++.

## Точки входа

- [Python-хук](tools/rules/hook.py) читает staged diff и запускает проверки из [cpp_layout.py](tools/rules/cpp_layout.py). У `cpp_layout.py` есть режим `--fix`.
- [Адаптер clang-tidy](tools/rules/clang_style.py) передаёт staged-содержимое через VFS overlay и ограничивает диагностики строками diff. Плагин и его [управляющий скрипт](../stylecheck/run.py) находятся в соседнем репозитории `../stylecheck`.
- [Тесты Python](tools/rules/test_hook.py) создают временные Git-репозитории. Плагин проверяет диагностики и исправления по парам `cases.cpp` и `expected.json` в [fixtures](../stylecheck/fixtures).
- Лимит 78 колонок и шаг табуляции 8 заданы в [каталоге](tools/rules/laws/catalog.json). Их используют [Python](tools/rules/cpp_layout.py) и [C++](../stylecheck/Support/Text.h).

Перед правками проверь состояние обоих репозиториев и прогони текущие наборы.

```sh
git status --short --branch
git -C ../stylecheck status --short --branch
PYTHONDONTWRITEBYTECODE=1 python3 tools/rules/test_hook.py
PYTHONDONTWRITEBYTECODE=1 python3 ../stylecheck/run.py test
```

## Каталог правил

Помести каталог в `tdesktop/tools/rules/laws/`. Добавь версию формата, общие параметры раскладки и стабильный ID каждого правила. Для правила запиши область действия, исключения, ожидаемую диагностику и условия предложения автоисправления. Укажи, какие реализации поддерживают правило и какие данные им нужны.

Используй JSON и JSON Schema. Храни исходный и ожидаемый C++ в отдельных файлах. Так тесты смогут проверять табы, CRLF и результат правки побайтно. Проверяй, что все файлы, на которые ссылается каталог, существуют, а ID правил и сценариев уникальны.

Минимальный сценарий выглядит так.

```json
{
  "id": "move-standalone-closer",
  "before": "fixtures/move-standalone-closer/before.cpp",
  "after": "fixtures/move-standalone-closer/after.cpp",
  "headers": ["fixtures/move-standalone-closer/calls.h"],
  "expect": {
    "python": [{"rule": "call.closing-parenthesis", "line": 5, "fix": true}],
    "clang": [{"rule": "call.closing-parenthesis", "line": 5, "fix": true}]
  }
}
```

Закрепи явные ожидания для сценариев без диагностики, с диагностикой без правки и с правкой. Для staged-сценария храни исходник родителя и версию из индекса. Вычисляй строки diff тем же способом, что установленный хук.

## Общий запуск проверок

1. Напиши один Python-runner, который читает каталог, проверяет схему и запускает выбранную реализацию. Передавай каталог плагину явным путём. Для семантических фикстур передавай нужные флаги C++ и заголовки. Указывай целевую платформу, когда она влияет на результат.
2. Сопоставь сообщения Python и имена проверок clang-tidy со стабильными ID правил. Сравнивай ID, место диагностики, наличие исправления и итоговые байты. Разбиение правки на диапазоны может отличаться между реализациями.
3. Отдельно показывай проверки, пропущенные из-за отсутствия clang-tidy, плагина или compile DB. В полном прогоне требуй доступности всех реализаций, нужных для выбранных сценариев. В быстром режиме показывай фактическое покрытие.
4. После fix-it проверяй исправленный исходник всеми применимыми правилами. Убедись, что повторный запуск сохраняет байты. Для пробельной правки сверяй токены и комментарии. Закрепи примеры с препроцессором и многострочными литералами.

Пиши ожидаемые результаты до реализации исправления. Когда меняется договорённость о стиле, обновляй формулировку правила и сценарии в одном изменении. Если правило реализовано в обоих движках, прогоняй обе реализации по общим фикстурам.

## Первый этап

| Правило | Что проверить |
| --- | --- |
| Ширина строки | 77, 78 и 79 колонок, табы и CRLF. Сверь вычисление ширины в Python и Clang. |
| Закрывающая скобка вызова | Отдельная строка с `)` после непустого списка аргументов даёт диагностику. `) \| rpl::…` проходит. Комментарий между последним аргументом и `)` блокирует fix-it. |
| Отступ веток тернарного выражения | Для многострочного логического условия без скобок `?` и `:` идут на один таб глубже логического продолжения. Измени в staged diff только строку с `&&` и проверь, что обе диагностики доходят до хука. |

Сначала запусти эти фикстуры на существующих реализациях. Перенеси примеры из текущих тестов и добавь сценарий взаимодействия. Автоисправление переноса вызова должно проходить проверку закрывающей скобки.

После сверки поведения подключи общие значения ширины к обоим движкам. Используй один источник параметров для сборки плагина и Python. Если C++ читает сгенерированный заголовок, проверь его соответствие каталогу.

Этап завершён, когда новый сценарий добавляется через каталог и файлы C++, оба движка используют общие значения ширины, а старые наборы тестов проходят. Прогони текущую серию форматирования `a2` по одному коммиту против его родителя. Зафиксируй проверенный диапазон и результаты хуков.

## Эксперимент с Bend 2

Начни эксперимент после появления общего набора фикстур. Возьми одну чистую операцию. Она получает токены, позиции и кандидата на перенос аргументов. В `LAWS.bend` потребуй, чтобы предложенный перенос сохранял порядок токенов и оставлял закрывающую скобку на строке последнего аргумента. Добавь положительный сценарий, в котором подходящий короткий вызов обязательно получает исправление.

Прогони [lawcheck](https://github.com/bendlib/bendlib#check-a-law-before-you-prove-it) на малых входах модели. Затем проверь доказательство по [руководству Bend](https://github.com/bendlang/bend/blob/main/guide/GUIDE.md#laws-and-proofs). Прогони адаптеры Tree-sitter и Clang на тех же C++-фикстурах. Доказательство относится к модели токенов. Реальные фикстуры проверяют, как парсеры строят для неё вход.

Оцени результат по двум признакам. Модель должна воспроизвести известный конфликт с висячей скобкой, а доказанная операция должна подходить обоим движкам без дублирования логики. Интеграцию Bend с pre-commit рассматривай после такого результата. Общий каталог и тесты можно принять отдельно от эксперимента.

## Результаты

Каталог и схема находятся в [tools/rules/laws](tools/rules/laws). Python читает
параметры раскладки из каталога. CMake читает тот же JSON и генерирует
`LayoutConfig.h` для плагина в соседнем `stylecheck`. С временным лимитом 77
Python сообщил о строке шириной 78, а clang-tidy убрал fix-it, который дал бы
строку этой ширины. [Команды запуска](tools/rules/laws/README.md).

| Проверка | Результат |
| --- | --- |
| Штатный набор Python-хука | 104 теста прошли |
| Штатные фикстуры clang-tidy | 273 сценария прошли в 12 наборах |
| Общий каталог | Python 19/19, clang-tidy 11/11, пропусков нет |
| Порог ширины | Python и C++ дали одинаковый результат на девяти одинаковых строках шириной 77–79 колонок с табами, LF и CRLF. |
| Staged-тернарное выражение | Изменена только строка с `&&`. Обе диагностики совпали в выводе pre-commit-хука и в экспорте fix-it. Правки дали ожидаемые байты. |
| Серия `a2` | Установленный pre-commit-хук вернул 0 для каждого из 22 коммитов диапазона `6fe1a9f85f^..ac3274e465`. |

Для серии `a2` каждый коммит проверен против первого родителя во временном
индексе. Clang использовал `out/clang-tidy/compile_commands.json` этого
чекаута и staged-содержимое через VFS overlay. Диапазон включает исправление
логического условия в предпросмотре бота, серию форматирования и коммиты хуков
между ними и после них.

Bend 2.0.40 и BendTT на Lean 4.34.0 подтвердили три закона. `lawcheck` 0.4.1
проверил по 150 малых входов для двух общих законов и один вход для обязательного
исправления короткого аргумента. Старая модель сохраняла исходный разрыв перед
скобкой. `lawcheck` уменьшил контрпример до разрыва в одну строку.

Tree-sitter и Clang выдали одинаковые токены и позиции для короткого аргумента
и вложенного вызова. Одна операция Bend проверила переносы, предложенные
действующими форматтерами Python и Clang. Ширина взята из фактической правки.
Прототип стоит запускать отдельной проверкой. Подключение к pre-commit добавило
бы зависимость от Bend, а выбор правки и её применение к исходным байтам
по-прежнему выполняли бы существующие форматтеры.

## Полный каталог

Каталог расширен до 26 правил. В нём 14 правил Python, включая проверки в
режимах edit, pre-commit и commit-msg, и все 12 проверок clang-tidy из
`../stylecheck` на `master` (`7067afb`).

В 45 фикстурах проверяется диагностика каждого правила в каждом заявленном
режиме. Общий прогон дал 45 успешных проверок Python и 22 clang-tidy. Для
пробельных правок runner сверяет токены и комментарии. Для инициализаторов
полей, переходов на `auto` и удаления повторного `[[nodiscard]]` он сверяет
точные байты и повторно запускает проверки на исправленном файле.

## Общее решение для закрывающей скобки

`closer.bend` формализует решение для отдельной закрывающей `)` у вызова с
аргументами. Адаптер передаёт четыре признака. Скобка стоит отдельно, хвост
строки содержит только закрывающие знаки, промежуток состоит из пробелов и
переносов, объединённая строка укладывается в лимит. Результат определяет,
пропустить случай, выдать диагностику или присоединить скобку.

Генератор вычисляет все 16 комбинаций и записывает таблицу в каталог. Python
читает её при запуске. clang-tidy получает её при сборке. Оба сохраняют свои
парсеры и проверяют, можно ли безопасно применить правку в данном контексте.
Для хука достаточно сгенерированной таблицы.

BendTT подтвердил пять законов правила и три прежних закона модели переноса.
Общие фикстуры проверяют диагностики и правки обоих движков, включая
комментарии, RPL, превышение ширины, CRLF и цепочки вложенных скобок.
В пробной сборке замена «присоединить» на «выдать диагностику» в таблице
отключила правку для одной и той же фикстуры в обоих движках.

## Автономная спецификация закрывающей скобки

[closing_parenthesis.py](tools/rules/laws/closing_parenthesis.py) получает
байты C++, разбирает вызовы закреплённой версией Tree-sitter, выбирает
диагностики по указанным строкам и выдаёт операции над точными диапазонами
байтов. [Схема результата](tools/rules/laws/closing_parenthesis.schema.json)
фиксирует формат для любого клиента. С `--fix` команда печатает исправленный
исходник.

Python-хук вызывает спецификацию напрямую. Адаптер clang-tidy передаёт
ей байты из Clang, включая staged-содержимое из VFS. Оба пути используют
один разбор, один расчёт ширины и одни байтовые правки. Bend по-прежнему
задаёт таблицу решения для прямого присоединения скобки.

Прошли 13 фикстур автономной спецификации, 85 проверок общего каталога,
105 тестов Python-хука и 280 сценариев плагина. Повторный прогон диапазона
`6fe1a9f85f^..ac3274e465` завершился с результатом 22/22.
